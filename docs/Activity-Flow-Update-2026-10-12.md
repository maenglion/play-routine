# Play Routine — 활동 배정·자녀 체크·부모 확인

작성일: 2026-10-12 (KST)

## 결론

**규칙 등록 다음의 실제 행동 기록 흐름을 연결했다.** 부모가 게시한 규칙을 자녀와 날짜·요일에 배정하고, 자녀가 했다고 알려주면 유보된다. 부모가 수치와 이유를 확인하면 해당 수행일에 예정 효과가 표시된다. **이 단계는 원장 정산을 하지 않으며 예정분을 사용할 수 없다.**

기존 실계정 가족·자녀 연결은 유지한다. 과거 Google Sheets 자료를 이관하거나 운영 규칙을 임의로 등록하지 않는다.

## 부모 화면

1. **규칙 등록**: 활동명·설명·측정 기준과 0~100 세 구간을 정의해 초안 저장 후 게시한다. 규칙은 가족 시간대 기준 다음날부터 효력이 생긴다.
2. **자녀에게 배정**: 활성 자녀·게시 규칙·시작일·종료일·반복 요일을 선택한다. 하루만 배정할 수도 있다. 새 배정은 다음날 이후부터 시작한다.
3. **날짜별 확인**: 자녀와 수행일을 선택한다. 자녀 체크가 없어도 부모가 직접 관찰한 사실은 확인할 수 있다. 점수와 **자녀에게 공개되는 이유**를 입력해야 한다.

새 버전을 게시해도 기존 배정의 평가 기준은 자동 변경되지 않는다. 기존 반복 배정을 적절한 날짜까지 종료하고 새 버전으로 새로운 배정을 만든다. 종료는 포함 날짜 기준이며 과거 기록을 삭제하지 않는다. 시작 전 배정을 완전히 취소하는 UI는 후속 단계다.

## 자녀 화면

- 배정된 실제 할 일과 설명·확인 기준·최대 보상 예정분을 표시한다.
- **했어요**는 수행 주장이다. 부모 확인 전에는 `HELD`이며 보상·차감이 확정되지 않는다.
- 부모·자녀의 체크가 없는 항목은 `MISSING`이다. 미체크 전체 화면 알림과 확인 버튼을 제공하며, 확인 후 계속 작업할 수 있다.
- 부모 확인 후 점수·결과·공개 이유·확인 시각을 표시한다.
- 진행·일정 탭에서 과거 수행일을 선택해 늦은 체크를 할 수 있다.
- 회색 티켓에는 부모 확인된 오늘의 양수 예정분만 표시한다. **사용 가능 잔액은 원장 연결 전이라는 표시와 `—`를 사용한다.** 실제 0분 잔액으로 가장하지 않는다.
- 티켓 외곽과 프로필은 무그림자다. 하얀 티켓 SVG 두 번째 레이어만 그림자를 유지한다.

## 상태와 판정

| 상황 | 처리 상태 | 효과 |
|---|---|---|
| 부모·자녀 모두 미체크 | MISSING | 미확인. 중립 판정도 패널티도 아님 |
| 자녀만 체크 | HELD | 부모 확인 대기. 효과 미확정 |
| 부모가 확인 | CONFIRMED | 고정된 규칙 버전으로 보상·무보상·패널티 예정분 산출 |
| 부모 확인 뒤 자녀가 늦게 보고 | CONFIRMED 유지 | 부모 결과는 보존. 보고 사건·revision만 추가 |
| 부모가 점수 정정 | 새 PARENT_VERIFIED 사건 | 이전 사건 보존. 최신 예정분 projection만 갱신 |

미확인과 평가된 무보상은 서로 다르다. 실제 중간 구간에는 `policy_effects` 행이 없어도 `NO_REWARD`·0분으로 정상 판정한다. 돈·물품·약 복용은 이번 평가 입력에 포함하지 않는다.

## 날짜와 무결성

- `business_date`: 실제 수행 날짜. 가족 시간대 기준 날짜다.
- `performed_at`: 알려진 실제 수행 시각만 입력하는 선택값. 모르면 NULL이다. 체크한 시각을 실제 수행 시각으로 가장하지 않는다.
- `recorded_at`: 서버가 기록한 시각.
- `parent_verified_at`: 부모가 확인한 시각.
- 과거 수행일을 오늘 확인해도 사건의 수행일을 오늘로 바꾸지 않는다.
- 배정마다 게시 `policy_rule_id`를 고정한다. 새 규칙이 과거 사건 기준을 바꾸지 않는다.
- 원본 사건과 배정 종료 이력은 수정·삭제할 수 없다.
- 요청 UUID는 행위자 단위로 유일하다. 같은 내용의 재시도는 중복 기록하지 않고, 같은 키로 다른 내용을 보내면 거절한다.
- 부모 확인은 `expected_revision`으로 동시 수정을 탐지한다. 충돌하면 자동 덮어쓰기하지 않고 새로고침을 요구한다.
- 배정 겹침은 동일 자녀·활동의 날짜 범위와 실제 공통 요일을 함께 검사한다.
- 조회는 날짜 하나의 occurrence를 필요할 때 생성한다. 아직 자정 자동 생성·정산 서비스를 구성하지 않았다.

## 권한과 CSV

확인된 Auth 계정과 ACTIVE 가족·principal·멤버십이 필요하다. 부모는 자기 가족 배정·확인만, 자녀는 자기 할 일 조회·수행 보고만 가능하다. 보기 전용 보호자는 활동 상세·규칙·확인·사진·CSV에 접근하지 못한다. 기존 상태판의 보기 전용 범위는 그대로 유지한다.

부모 CSV에 **활동 배정 일정**과 **활동 체크·부모 확인 이력**을 추가했다. 수행일·입력일·규칙 ID·공개 이유·예정분·`NOT_SETTLED`를 포함하며 비밀번호·토큰·실제 잔액은 포함하지 않는다. 이력 CSV는 동일 occurrence의 여러 사건을 별도 행으로 표시한다. 수식 접두어와 앞 공백·제어문자는 CSV 수식 주입을 막도록 처리한다.

## DB와 재현 시험

추가 migration: `0009_activity_assignments_and_review.sql`

추가 테이블:
- `activity_assignments`
- `activity_assignment_end_events`
- `activity_occurrences`
- `activity_occurrence_events`

서버 DB 인증정보는 안전한 환경변수로만 제공한다. 로컬에 SQL 비밀번호를 하드코딩하지 않는다.

기본 코드 검증:

```sh
pnpm check
pnpm test
pnpm build
```

활동 실DB 시험은 명시적으로 실행한다. fixture를 한 트랜잭션으로 만들고 **모두 롤백**한다.

```sh
RUN_LIVE_ACTIVITY_TESTS=1 pnpm exec vitest run server/activity-flow.live.test.ts
```

전체 실서비스 회귀시험:

```sh
RUN_LIVE_ACTIVITY_TESTS=1 RUN_LIVE_SUPABASE_TESTS=1 RUN_LIVE_GUARDIAN_TESTS=1 RUN_LIVE_AUTH_CALLBACK_TESTS=1 pnpm exec vitest run --reporter=basic
```

실DB 시험끼리는 공통 advisory lock으로 직렬화한다. 날짜 fixture를 위한 일시적 trigger 변경 때문에 병렬 시험 간 교착이 발견되어 보강했다. 운영 부모 배정 로직의 오류와 시험 fixture 잠금 충돌은 구분한다.

## 아직 하지 않은 것

- 원장·정산·정산 후 상쇄·일별 snapshot의 물리 구현과 운영 자정 배치.
- 미분류 잔차의 case·사람 결정·ref 편입과 소급 원장 연결.
- 실제 사용 가능 잔액·실물 쿠폰 발행·사용.
- 약 복용의 별도 사실 기록 영역.
- 운영자의 실제 규칙 내용 입력과 자녀에게 배정. 임의 시험 활동을 실가족에 넣지 않는다.
- 실제 사용자 브라우저에서 새 배정의 체크·부모 확인을 완료했다는 주장. 개발 미리보기 UI와 실제 DB rollback 시험은 별도 검증이다.

**바로 할 한 단계:** 부모 화면에서 첫 활동 하나를 규칙으로 저장·게시한다. 새 활동을 오늘로 소급 배정하지 않고 다음날 시작한다.
