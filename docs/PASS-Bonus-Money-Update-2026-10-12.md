# PASS·특별보너스·돈 보상 변경 — 2026-10-12

## 확정 운영 방식

- **PASS**: 부모가 그날 선생님의 문제 지적이 없었음을 확인하면 등록한 기본 시간 보상이 예정된다. 숫자 점수·하한·상한 입력은 필요 없다.
- **미확인**: 연락·체크 데이터가 없다는 사실만으로 자동 PASS 또는 패널티를 만들지 않는다. 부모가 확인한 뒤 PASS를 선택한다.
- **문제 있음 / 확인 필요**: 기본 보상 없음. 자동 차감 없음. 부모 확인 이유·수행일·입력일·revision을 보존한다.
- **칭찬**: 기본 PASS 판정과 분리하여 부모가 특별보너스 쿠폰을 발행한다. 칭찬 횟수·금액 가산 공식을 운영 화면에 강제하지 않는다.
- **돈 보상**: 일·주·월·특별 이벤트를 별도 지급 기록으로 관리한다. 금액은 부모가 직접 입력한다. 시간 보상과 섞거나 자동 송금하지 않는다.

기존 숫자 루브릭 규칙은 변환하거나 삭제하지 않았다. 새로운 약속 규칙은 기본 선택인 **약속 PASS / 확인 필요**로 등록한다. 기존 배정은 고정된 옛 정책을 유지하므로 새 정책 게시 후 기존 배정을 종료하고 새 정책을 배정해야 한다.

## 화면

부모 대시보드 상단 **특별보너스·돈 보상**에서 다음을 관리한다.

| 영역 | 입력·동작 |
| --- | --- |
| 주간 돈 보상 | 자녀·기준일·이번 주 잘했음·약속한 주간 금액 |
| 일·월·특별 이벤트 | 자녀·기간·금액; 특별 이벤트는 제목으로 구분 |
| 특별보너스 쿠폰 | 자녀·발행일·이름·권리 종류·수량·간단한 이유 |
| 지급 기록 | 지급 예정·실제 지급 완료·미지급 예정 취소 |
| 쿠폰 기록 | 선택 자녀의 발행·사용·취소 상태 |

주간은 가족 시간대의 **월요일~일요일**이다. 주 전체가 끝나기 전에는 대기 초안이며 지급 예정으로 확정하지 않는다. 초안 또는 미지급 주간 금액은 수정할 수 있고 이전 값은 감사 이벤트로 남는다. 지급 완료 기록은 조용히 수정·취소하지 않는다.

자녀 화면의 **내 보상 기록**에서 돈 보상과 쿠폰을 별도로 확인한다. 자녀나 보기 전용 보호자는 지급·쿠폰 발행·사용 처리를 할 수 없다. 현재 보호자에는 수동 금전·쿠폰 내역 자체를 노출하지 않는다.

## 데이터·보안

- `0010~0011`: PASS_FAIL 측정 및 전용 저장·확인 RPC.
- `0012`: 수동 금전·보너스 쿠폰·불변 감사 이벤트.
- `0013`: 미지급 주간 수정·실제 지급일 검증.
- `0014~0016`: 실DB 시험에서 발견한 PASS 컬럼 충돌·감사 enum·UNION 정렬 오류 보정.
- 이미 적용한 migration은 수정하지 않고 추가 보정 migration을 적용했다.
- 가족·자녀·principal·이메일 인증 상태와 역할을 DB에서 검증한다.
- RPC-only 원시 금전 테이블 접근 차단, 가족별 격리, 요청 멱등성, 1회 지급·사용 처리를 적용했다.
- 동일한 실패 요청의 재시도는 같은 요청 키를 사용한다. 브라우저 새로고침 후 별도 발행까지 전역 중복으로 간주하지는 않는다.
- 시험 fixture는 트랜잭션 롤백한다. 실제 부모·자녀 계정은 삭제하거나 시험 지급을 만들지 않았다.

## 중요한 미완료 경계

**PASS 기본 시간은 아직 사용 가능한 원장 잔액이 아니라 부모 확인된 예정분이다.** 일반 시간 원장·자정 정산·사용 가능 잔액 연결은 다음 단계다.

특별보너스의 시간 쿠폰은 일반 티켓 잔액에 합산하지 않는 별도 이용권이다. 부모가 실제 사용을 확인해 상태를 바꾼다. 돈 기록의 ‘지급 완료’는 앱 밖에서 실제로 지급한 사실의 기록이며 송금 기능이 아니다.
