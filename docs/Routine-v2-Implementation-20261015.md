# 데일리·Quest 룰 등록 v2 — 20261015

**기준:** 사용자가 승인한 `Rule-Registry-Change-20261015-1.md`. 구현·DB 적용·종합시험·GitHub·양쪽 공개 배포 완료.

## 이번 변경의 핵심

**데일리는 하루의 PASS 스티커를 기간별로 모으고, Quest는 부모가 확인한 수치 조건을 판정한다.** 활동 하나를 보상 종류마다 복제하지 않는다. 조건 하나에 보상 1개 또는 2개를 연결하며, 두 번째 보상과 추가 달성 구간은 선택사항이다.

| 관계 | 데일리 | Quest |
| --- | --- | --- |
| 수행 판단 | 부모 PASS / 문제 있음 | 부모의 0~100 퍼센트·수량 점수 |
| 자녀의 `했어요` | 보고 사건과 hold | 보고 사건과 hold |
| 칭찬 | PASS 1개 + 확인된 칭찬 1개 | 별도 자유 특별보너스 유지 |
| 미확인 | 스티커 수 미확정 | 점수 미확정 |
| 조건 판정 | 활동·룰 버전·자녀·달력 기간의 스티커 합계 | 해당 수행건의 수치와 비교 연산자 |
| 보상 | 기간 종료 후 부모가 `기간 마감·권리 확인` | 부모가 조건을 확인할 때 보상권 기록 |
| 구간 미달 | 보상 없음, 스티커 회수 없음 | 명시한 중립·패널티 후보·보상 구간 구별 |

PASS를 매일 확인했다고 주간 보상이 매일 지급되지 않는다. 주간 5개 기본 조건과 추가 3개 조건은 **5개 / 총 8개**로 저장한다. 8개를 달성하면 기본 보상과 추가 보상이 함께 인정되지만, 이미 만든 기본 보상권을 다시 만들지 않는다. 스티커를 교환 후 0으로 초기화하지 않는다.

## 부모의 새 등록 흐름

| 단계 | 입력·행동 | 저장의 의미 |
| --- | --- | --- |
| 1. 활동·측정 | 데일리/Quest, 활동 이름, 분류, 아이 키워드, 상세 확인 기준 | 미완성 임시저장 가능 |
| 2. 조건·보상 | 기간·스티커 기준 또는 수치 조건, 보상 1~2개, 추가 구간 | 두 번째 보상 제거 가능; 0개인 초안도 저장 가능 |
| 3. 검토·게시 | 저장한 초안 검토, 내일부터 게시 | 완성도 검증, 게시본 불변 |
| 배정 | 게시한 룰·자녀·시작일·요일 | 선택한 버전 고정; 기존 배정 자동 교체 안 함 |
| 수행일 확인 | PASS·칭찬 또는 Quest 수치, 자녀에게 보일 이유 | 실제 수행일과 입력·확인 시각 분리 |
| 권리 이행 | 돈·시간·포인트·약속별 이행 완료 표시 | 앱 밖 지급·사용 확인; 자동 송금 아님 |

단계별 임시저장과 나중에 이어쓰기를 지원한다. 편집 중인 내용을 저장하지 않은 상태에서 이전 저장본을 게시하지 못하게 한다. 게시본 변경은 새 버전으로만 진행하며 가족 시간대 기준 내일부터 효력이 생긴다.

## 강화물과 독립 보상권

| 강화물 타입 | 예 | 취급 |
| --- | --- | --- |
| `WON` | 부모가 정한 돈 보상 | 원 단위, 지급 예정 권리와 실제 지급 구별 |
| `MIN` | 시간 | 분 단위, 일반 시간 잔액과 별도 |
| `POINT` | 특정 서비스 포인트·머니 | 등록한 서비스 단위 유지 |
| `STRING` | 소원·함께 가기 | 약속 내용과 이행 상태 |

같은 Quest 조건에 원화와 시간을 붙였다면 **둘 다 받을 권리**다. 두 가지 중 아이가 하나를 고르는 구조가 아니다. 현금 지급 완료가 시간 사용 완료를 뜻하지 않는다. 자유 특별보너스 쿠폰은 조건 연계 보상과 다른 출처로 그대로 유지한다.

중복 방지는 `자녀 + 룰 버전 + 수행건/기간 + 조건 + 보상 항목`을 기준으로 한다. 동일 요청 재전송은 같은 멱등 키로 처리하며, 이미 만들어진 권리는 같은 조건 확인으로 중복 생성하지 않는다.

## 정정·보존·권한

부모 확인은 revision 검증과 append-only 사건으로 기록한다. 낮춘 정정으로 자격이 달라지면 이미 만들어진 권리를 지우거나 지급된 돈을 자동 회수하지 않고 재검토 상태로 보존한다. 수정된 근거에 따라 다시 자격을 확인하더라도 기존 권리 ID와 지급 이력을 유지한다.

기존 가족 연결·룰·배정·사진·자유 보너스·수동 돈 보상은 삭제하거나 일괄 변환하지 않는다. 기존과 신규 등록기에서 같은 자녀·활동·날짜·요일에 중복 배정하는 것도 서버에서 양방향으로 차단한다. 가족 전환과 날짜 변경 시 늦게 도착한 응답이 다른 가족·날짜의 편집 상태를 덮지 않도록 보호한다.

부모만 등록·게시·배정·확인·보상 이행·CSV를 수행한다. 자녀는 자신의 수행 보고와 조회만 가능하다. 보기 전용 보호자는 기존 상태창 권한을 유지하며 새 룰이나 보상권을 수정·발행할 수 없다. 이메일·토큰·DB 비밀번호는 기록이나 공개 소스에 넣지 않는다.

## 자녀 화면과 CSV

자녀는 아이 키워드·부모 확인 기준, 현재 활동별 스티커 합계, 기본·추가 구간, 각 보상 항목, 부모 확인 이유와 시각을 본다. 미확인과 0개 확정을 구별하고, 신규 활동도 부모 확인 진행률에 반영한다.

부모의 기록 내려받기에 다음 두 CSV를 추가한다.

| 데이터셋 | 내용 |
| --- | --- |
| `routine-records` | 수행일, 룰 버전, 부모 확인·칭찬·스티커 사건, 확인 이유·입력시각 |
| `routine-rewards` | 조건별 강화물 단위·값, 보상권, 이행·재검토 감사 이력 |

두 CSV 모두 인증된 부모의 가족 필터를 적용하고 악성 스프레드시트 수식을 무력화한다. 예정분·보상권을 잔액으로 표시하지 않는다.

## 구현 경계

일반 시간 원장, 자정 정산, 실제 시간 사용, 자동 송금·충전, 여러 활동을 섞는 스티커 묶음 집계, 잔차·AI 분류는 이번 구현이 아니다. 주간은 월~일, 월간은 달력 월이다. 특별 이벤트 데일리는 현재 하루 배정으로 처리한다. 기간을 마감할 때 이미 부모가 확인한 스티커만 집계하며, 늦게 확인한 추가 스티커는 원래 수행일의 기간으로 재확인한다.
