# Play Routine Figma 핵심 UI 분석 v0.1

## 1. 자료 상태

사용자가 제공한 Figma 노드는 `42:874`, `42:2052`, `42:1352`, `42:312`다. 현재 실행 환경에서 Figma 링크는 CloudFront 403으로 차단되었고 별도 Figma 커넥터도 없었다. 따라서 같은 Figma 프로젝트에서 이전에 업로드된 `frame.webp`, `code.jsx`, 노드별 로컬 자산과 사용자의 추가 지시를 기준으로 핵심 UI를 구현한다.

## 3. 핵심 화면 대응

| Figma 요소 | 현재 서비스 대응 |
|---|---|
| 이름·작은 프로필 사진 | Supabase 자녀 profile + S3 avatar |
| 알림 종 | 이번 범위에서 제외 |
| 큰 티켓 | `현재 보유량`과 회색 `오늘 모으는 중`을 한 티켓에서 분리 |
| 오늘의 루틴·완료·미완료 탭 | assignment 상태 필터; 테이블 구현 전 0건 empty state |
| 루틴 카드 | `DAILY_STUDY`, `SPECIAL_SCHEDULE`, `LIFE_HABIT` 카드 |
| 진행률 | 당일 assignment의 확정·미확인 상태 집계 |
| 하단 플로팅 바 | 홈·진행·일정·프로필; 종은 포함하지 않음 |
| 부모 화면 | 같은 크림·보라·슬레이트 토큰으로 초대·CSV·자녀 관리 카드 구성 |

## 4. 추가 사용자 결정

하단 바는 콘텐츠를 가리지 않도록 화면 최하단 safe area 바로 위에 배치하며 높이와 좌우 여백을 Figma보다 조금 줄여 가독성을 확보한다. 자녀는 자신의 작은 프로필 사진을 등록할 수 있다. 메인 티켓에서 오늘 적립 예정값은 회색으로, 현재 사용 가능한 보유량은 보라 강조로 표시한다.

## 5. 구현 원칙

날짜별 화면은 새 테이블을 만들지 않고 기존 session·membership 상태에 따라 렌더링한다. 실제 활동·원장 테이블이 적용되기 전에는 수치를 조작하지 않고 모두 0과 empty state로 표시한다. 프로필 사진은 S3에 저장하고 DB에는 key와 URL만 저장한다.

## 6. 모바일 시각 검증

390×844 뷰포트에서 인증 화면과 자녀 메인을 검증했다. 인증 화면은 크림 배경, 보라 역할 탭, 민트 안내 카드가 안정적으로 보였고 작은 화면에서 가로 잘림이 없었다.

자녀 메인에서는 작은 원형 프로필, 회색 `오늘 모으는 중`, 보라 `현재 보유량`, 라일락·민트 루틴 카드, 진행률 바가 Figma 톤으로 표시됐다. 숫자와 할 일이 아직 없으므로 실제 DB 값 대신 모두 0과 준비 empty state를 사용했다. 전체 페이지 캡처에서는 하단 fixed 플로팅 바가 도구 동작상 숨겨지므로 별도 viewport 캡처에서 확인한다.

390×844 viewport 캡처에서 하단 플로팅 바는 좌우 12px, 높이 58px로 safe area 바로 위에 표시됐고 첫 화면의 마지막 진행률 항목을 가리지 않았다. 종 아이콘은 포함하지 않았다.

1280×720 부모 관리자 화면에서는 상단 슬레이트 헤더, 라일락·민트·슬레이트 상태 카드, 보라 초대 CTA, 자녀 프로필 목록과 CSV 내려받기 영역이 한 화면에 표시됐다. 입력과 버튼이 겹치거나 잘리는 문제는 없었다.
