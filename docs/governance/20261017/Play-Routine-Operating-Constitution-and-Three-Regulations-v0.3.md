# Play Routine 운영 기본법 및 Task·Quest·Lifestyle 규정 v0.3

**상태: 2026-10-17 사용자 수정 요약과 추가 첨부의 확인 내용을 반영한 정리본. Lifestyle 제7조에 기록 전용 영역과 별도 생활습관 규칙의 분리 적용을 명시하고, 10장의 확정/대기 경계를 갱신했다. 나머지 조문은 v0.1 그대로다. 전체 규정 승인·Grok 2차 검증·운영 적용은 미완료다.**

여기서 ‘법령’은 국가 법률이 아니라 Play Routine 내부의 운영 규범을 뜻한다. 이번 문서는 공통 목적과 규칙의 권한 관계를 먼저 정한다. 구체적 활동명·금액·점수 경계·횟수는 사용자가 제공할 초기 시행령으로 확정한다. 이전 테스트의 숫자는 초기 시행령으로 자동 승계하지 않는다.

## 1. 규정의 위계와 정본

### 1.1 상위 운영 기본법 — `PR-BASIC`

습관 형성이라는 목적, 보상·중간지대·패널티의 의미, 판단 상태, 복수 보상과 스티커의 공통 원칙, 변경·폐지·과거 기록 보존 원칙을 정한다. 하위 규정과 시행령은 이를 위반할 수 없다.

‘한 조건에 복수 보상을 연결할 수 있고 두 번째 보상은 필수가 아니다’는 공통 원칙이다. 반면 ‘이 조건을 달성하면 120분과 30,000포인트를 준다’는 개별 시행령이다. 스티커의 종류별 식별과 기록 보존은 공통 원칙이고, 어느 활동에서 어떤 스티커를 몇 회 인정할지는 하위 규정 및 시행령에 속한다.

### 1.2 세 가지 하위 규정

- **Task 규정 — `PR-TASK`:** 반복 수행과 작은 성공을 쌓는 과제의 인정 체계.
- **Quest 규정 — `PR-QUEST`:** 결과·정확도·시간·과정의 질과 주간·월간 목표를 평가하는 체계.
- **Lifestyle 규정 — `PR-LIFESTYLE`:** 생활습관의 부모 인정, 스티커와 발생형 보상·패널티, 인플레이션 관리 체계.

세 규정은 독립적으로 존재하되 모두 기본법에 종속된다. ‘일일·주간·월간·특별 이벤트’는 별도의 주기다. 주간이라는 이유만으로 Quest, 하루 반복이라는 이유만으로 Lifestyle이 되지 않는다.

### 1.3 각 규정의 초기 시행령

사용자가 활동별 텍스트를 제공한다. Manus는 원문을 보존하면서 해당 규정의 조문과 연결하고, 모호한 조건·공백·충돌을 표시한다. 시행령은 활동의 기준·단위·주기·인정 횟수·보상·차감·예외를 구체화한다. 시행령이 기본법의 금지 사항을 조용히 바꿀 수는 없다.

정본의 순서는 **승인된 기본법 → 승인된 해당 하위 규정 → 승인된 해당 시행령 버전 → 해당 버전으로 발생한 기록**이다. UI, 코드의 기본값, 과거 시트 또는 시뮬레이션이 승인된 문서보다 우선하지 않는다.

## 2. 상위 운영 기본법 `PR-BASIC`

### 제1조 목적

이 서비스는 규칙 이행을 어려워하는 아이가 생활과 학습을 작은 성공 경험으로 익히도록 지원한다. 목적은 보상 숫자를 크게 만들거나 실패를 많이 검출하는 것이 아니라 지속 가능한 습관 형성이다. 부모의 운영 부담과 아이의 설명 가능한 경험을 함께 고려한다.

### 제2조 규정과 사실의 분리

규정은 ‘어떤 경우 무엇을 인정할 것인지’이고, 사건은 ‘무슨 일이 있었는지’이다. 규정이 바뀌어도 사건은 없어지지 않는다. 하나의 사건에 다른 목적의 평가가 연결될 수 있으나 같은 성취를 중복 보상하는 정책은 명시되어야 한다.

### 제3조 세 가지 결과

**보상**은 확인된 사실이 보상 인정 조건을 충족한 결과다. **중간지대**는 사실이 확인되었으나 보상도 차감도 발생하지 않는 정상 결과다. **패널티**는 별도로 정한 위반·미달 조건을 확인하고 승인한 차감 결과다.

중간지대는 부분 수행과 합리적 여지를 인정하고, 모든 미달을 처벌로 바꾸지 않기 위해 둔다. 중간지대의 기록도 학습과 습관 통계에 활용할 수 있다. 중간지대는 실패 기록을 숨긴 칸도, 정의하지 못한 사건의 쓰레기통도 아니다.

### 제4조 중간지대가 없는 규정

모든 개별 규칙이 세 결과를 모두 가져야 하는 것은 아니다. 기본법은 세 결과를 허용하고, 해당 시행령은 필요한 결과 구조를 명시한다.

보상/패널티 두 구간만 쓰는 Quest는 중간지대를 두지 않는 교육적 이유와 완전한 경계를 명시한다. 단순히 회색 칸을 생략했다는 이유로 모든 보상 미달이 패널티가 되지 않는다. 스티커 지급/미지급처럼 두 선택으로 구성된 인정 방식에서는 ‘미지급’을 차감으로 간주하지 않는다. 별도의 수치 중간 구간이 없더라도 무효과 상태는 설명되어야 한다.

### 제5조 중간지대와 처리 상태의 구별

‘확인했고 이번에는 보상이 없다’와 ‘아직 확인하지 않았다’는 다르다. 미입력, 부모 미확인, 적용 제외, 사실 분쟁, 규정 충돌, 필수 측정 미상은 처리 상태이며 보상·중간지대·패널티 중 하나로 추정하지 않는다.

초과 수행은 기록할 수 있으나 인정 한도를 넘긴 추가 보상은 없을 수 있다. 이것도 패널티가 아니다. ‘조건 미달’과 ‘인정 한도 초과’는 무효과의 이유를 구별해 남긴다.

### 제6조 부모 확인과 재량

부모가 해당 규정의 목적에 따라 최종 사실 또는 인정 여부를 확인한다. 자녀 자기보고와 부모 확인을 별도 기록한다. 체크가 없다는 이유만으로 미수행이나 위반을 확정하지 않는다.

재량이란 그날의 상황을 고려하여 인정할 수 있다는 뜻이지, 알려주지 않은 기준으로 과거 보상을 회수할 수 있다는 뜻이 아니다. 부모는 언제 무엇을 인정·미인정·정정했는지 기록한다. 통상적인 PASS에는 과도한 서술을 강제하지 않되, 차감 승인과 정정에는 사유를 남긴다.

### 제7조 보상 종류와 복수 보상

시간·돈·서비스 포인트·소원 또는 체험 같은 보상은 단위와 제공 방식을 구별한다. 원, 분, 포인트를 자동 환산하거나 하나의 숫자로 더하지 않는다.

하나의 조건에 복수 보상을 연결할 수 있다. 현재 기획의 1~2개 보상에서 두 번째 보상은 선택이며, 연결했다면 두 보상 모두 해당 조건의 결과다. ‘두 종류 중 하나만 선택’인지 ‘둘 다 제공’인지는 개별 시행령에 명시해야 한다. 복수 보상이라고 인정 횟수까지 두 번 소비하지 않는다.

### 제8조 기본 달성과 추가 달성

기본 조건 달성과 추가 조건 달성을 구별한다. ‘스티커 5개에서 기본 보상, 8개에서 추가 보상’처럼 누적형으로 정했다면 기본 보상을 다시 발행하지 않고 추가분만 연결한다. 8개 구간의 금액이 ‘추가액’인지 ‘최종 총액’인지는 시행령에 명시한다.

서로 배타적인 수준별 보상과 누적 보상은 같은 방식으로 계산하지 않는다. 겹친 조건을 입력 순서로 임의 선택하거나 자동 상계하지 않는다.

### 제9조 스티커의 역할

스티커는 인정의 표식이며 곧바로 시간·돈 자체가 아니다. 스티커의 종류와 아이콘은 별개다. 같은 그림이라도 학교·학습·생활습관의 종류가 다르면 합산 대상은 자동으로 같아지지 않는다.

스티커에는 어떤 규정·활동·사건·부모 확인·시행령 버전에서 발생했는지 남긴다. 주간·월간 합산에는 시행령이 정한 종류 또는 활동 범위만 포함한다. PASS 인정과 칭찬 특별보너스를 자동으로 합쳐 스티커 수를 늘리지 않는다.

### 제10조 인플레이션과 한도

실제 발생·수행 횟수와 보상 또는 패널티 인정 횟수는 별개다. 하루 네 번의 사건을 남기면서 두 번만 보상할 수 있다. 횟수 제한과 총 분·원·포인트 제한도 별개다.

한도는 활동·종류·자녀 전체 중 어느 범위에 적용되는지, 일·주·월·이벤트 중 어느 기간인지 명시한다. 한도가 없으면 ‘없음’을 명시한다. 정하지 않은 한도를 코드에서 추정하지 않는다. 부분 보상을 허용할지 조건 전체를 인정하지 않을지도 시행령으로 정한다.

### 제11조 패널티

패널티는 보상을 받지 못했다는 사실과 동일하지 않다. 확인된 위반·미달의 기준, 차감 단위, 인정 횟수, 상한, 승인 절차를 명시해야 한다. 단순 미체크나 스티커 미지급에서 자동 발생시키지 않는다.

이미 받은 스티커·쿠폰·외부 보상을 다른 위반의 이유로 자동 몰수하지 않는다. 과거에 문제가 된 전액 몰수·무제한 배수 차감을 초기 시행령으로 자동 승계하지 않는다. 차감의 잔액 하한과 미차감 잔여량 정책은 별도로 명시한다.

### 제12조 시간·기간·정산

실제 수행일, 입력일, 부모 확인일, 기간 평가일, 정산 실행일, 잔액 효력 시점을 구별한다. 일·주·월·이벤트의 경계와 시간대는 시행령 또는 공통 운영 시행령으로 명시한다.

일·주·월 보상 판정과 자정 원장 정산은 다른 절차다. 자정 배치는 확정되고 승인된 효과만 중복 없이 반영한다. 체크 없음이나 미해결 잔차를 마감했다는 이유로 실패·패널티로 바꾸지 않는다. 늦은 확인은 실제 수행일에 귀속하되 과거의 사용 가능 잔액을 덮어쓰지 않는다.

### 제13조 원장과 실제 이행

달성권, 예정 적립, 사용 가능한 잔액, 외부 보상 이행은 서로 다르다. 현금·서비스 포인트·체험의 이행 기록은 실제 송금·충전·예약 자체가 아니다.

확정 원장은 수정하거나 삭제하지 않는다. 정정은 원거래를 참조하는 상쇄와 필요한 새 거래로 남긴다. 이미 외부 이행한 보상은 자동 회수하지 않고 별도 검토한다. 마감 재실행이나 버튼 재전송이 중복 발행·중복 차감을 만들면 안 된다.

### 제14조 변경·개정·폐지

규정과 개별 시행령은 신규 제정, 개정, 폐지될 수 있다. 각각 영구 식별번호와 버전, 원문, 시행일, 변경 사유, 승인자, 이전 버전 관계를 보존한다. 폐지 번호는 재사용하지 않는다.

‘삭제’는 시행을 종료하는 **폐지 사건**으로 기록한다. 화면에서 숨기더라도 과거 기록을 설명하는 문서는 남긴다. 게시 후의 내용을 덮어쓰지 않는다. 새 버전은 지정한 미래 효력 시점부터 적용한다.

### 제15조 잔차

잔차는 현재 승인된 규정으로 분류·측정·판정할 수 없는 질문이다. 원사건을 보존하고 질문을 연결한다. 확정 중간지대, 단순 미확인, 한도 초과를 모두 잔차로 합치지 않는다.

필수 판단이 불가능하면 해당 효과만 보류한다. 이미 규정과 보상 근거가 명확한데 부가적 스킬 관계만 미정인 경우까지 모든 처리를 멈추지 않는다. 기존 규정 편입, 새 규정 제정, 기록만 유지, 오류·중복 종결은 각각 사람의 결정과 적용 이력으로 남긴다.

### 제16조 검토와 승인

Manus는 1차 정리·충돌 표시·실행 조건 정규화를 담당한다. Grok은 같은 원문과 초안을 받아 2차 검증한다. 두 모델의 의견은 승인된 규정과 같지 않으며 최종 결정은 사용자에게 있다.

검증 중에는 규정을 게시하거나 부모 대신 차감을 승인하지 않는다. 두 검토가 다르면 어느 문구에서 어떤 결과가 달라지는지 남기고 확정 전 임의 선택하지 않는다.

## 3. Task 규정 `PR-TASK`

### 제1조 대상과 목적

Task는 반복 수행과 과정의 습관화를 통해 작은 성공을 쌓는 과제다. 매일 학습, 주간 학습, 일회성 Special을 포함할 수 있다. 주기는 달라도 수행·과정 인정이 핵심이면 Task다.

### 제2조 인정 방식

기본은 부모가 ‘이번 수행을 인정한다/아직 인정하지 않는다’를 확인하는 방식이다. PASS 판단에 붙은 확인 기준은 아이가 이해할 수 있는 행동으로 설명한다. 백분율·5점 척도를 모든 Task에 일괄 강제하지 않는다.

### 제3조 보상과 무보상

약속한 수행 인정은 시행령이 정한 스티커 또는 기본 보상과 연결한다. 일부 수행이나 미인정 시 보상 없음이 가능하다. 기록은 남기며, 미인정을 아이 전체의 실패로 표현하지 않는다.

### 제4조 패널티의 경계

Task 도식의 ‘실패하지 않는 작은 성공’과 패널티 막대는 동일 축에서 무조건 결합하지 않는다. **1차 제안은 수행 미달 자체는 무보상·재도전으로 두고, 필요하다면 별도로 정의한 위반만 패널티 대상에 연결하는 것이다.** Task 미달 자체에도 차감을 둘지 여부는 사용자 초기 시행령과 Grok 검증에서 명시적으로 확정해야 한다.

### 제5조 반복·회차·특별 이벤트

실제 회차를 별도로 기록하고 한 번의 체크를 여러 날의 수행으로 복제하지 않는다. Special은 이벤트 고유번호와 대상 기간을 가진다. 보상 인정 횟수와 수행 횟수는 구별한다.

### 제6조 목표와의 관계

같은 Task의 사실이 Quest 주간·월간 목표의 입력이 될 수 있다. Task의 수행 인정과 Quest의 목표 달성은 별도 조건·출처로 연결한다. 두 결과를 함께 보상하려면 그 중첩을 시행령에 명시한다.

### 제7조 시행령 필수 내용

Task 시행령에는 목적, 대상 행동, 수행/과정 인정 기준, 확인 주체, 주기와 회차, 스티커 또는 기본 보상, 인정 한도, 무보상 이유, 적용 제외, Quest 기여 여부와 변경 효력일을 적는다. 패널티가 있으면 제4조와 기본법 제11조에 맞춰 별도 기준을 적는다.

## 4. Quest 규정 `PR-QUEST`

### 제1조 대상과 목적

Quest는 결과나 과정의 질을 명시적 기준으로 평가하는 과제다. 정확도·정답 수·소요시간·자기주도성 등의 조합과 주간·월간 목표를 다룬다. 일회성 시험도 질 평가가 핵심이면 Quest다.

### 제2조 측정과 평가

수량, 백분율, 시각, 소요시간, 필요할 때의 척도 수준을 구별한다. 5점 척도를 쓰면 각 수준의 관찰 가능한 의미를 시행령에 적는다. 한 숫자가 다른 종류의 측정값을 대신하지 않는다.

### 제3조 복수 조건

‘정답 수 이상 AND 소요시간 이내’와 ‘정답률 이상’은 다른 규칙이다. AND/OR, 경계 포함 여부, 필수·선택 기준을 명시한다. 설명 문구와 구조화된 조건이 다르면 게시하지 않고 검토한다.

### 제4조 결과 구간

보상·중간지대·패널티를 둘 수도 있고, 근거가 명시된 보상·패널티 두 구간으로 정할 수도 있다. 후자에서는 유효한 측정 전체가 정확히 한 구간에 들어가야 한다. 미측정·미확인은 어느 구간에도 넣지 않는다.

### 제5조 조건과 보상

한 조건에 하나 또는 두 보상을 연결할 수 있으나 두 번째는 선택이다. 기본 달성, 추가 달성, 수준별 배타 보상 중 무엇인지 명시한다. 겹친 배타 조건은 먼저 입력한 조건을 임의 정본으로 채택하지 않는다.

### 제6조 주간·월간 목표

주간·월간 Quest는 목표, 기간, 대상 Task 또는 스티커 종류, 집계 방식, 예정 분모, 적용 제외를 먼저 정한다. 완료율이나 준수율은 예정·확정·미확인을 구별해 계산한다. 기간이 끝났다는 사실만으로 미확인 회차를 실패로 바꾸지 않는다.

### 제7조 후기 평가

늦은 채점은 원 수행·목표 기간에 연결하고 당시 시행령 버전으로 판단한다. 나중에 기준을 낮추거나 높인 새 규정을 과거 결과에 자동 적용하지 않는다. 과거 적용이 필요하면 별도의 정정 결정으로 남긴다.

### 제8조 시행령 필수 내용

Quest 시행령에는 목적, 평가 축·단위, 경계와 논리식, 평가 시점, 기간과 집계 범위, 결과 구조 및 중간지대 유무의 이유, 각 조건의 보상·차감, 한도, 예외와 정정 방법을 적는다.

## 5. Lifestyle 규정 `PR-LIFESTYLE`

### 제1조 대상과 목적

Lifestyle은 생활 행동을 유지·개선하고 반복 보상·차감의 과잉 누적을 조절하는 규정이다. 보상 인정은 부모의 상황 판단을 허용한다. 모든 생활습관을 5점 척도로 점수화하지 않는다.

### 제2조 PASS의 두 선택

부모의 기본 판단은 **스티커를 준다/주지 않는다**다. ‘주지 않음’은 스티커 0의 확인 결과이며 기존 스티커 회수나 차감이 아니다. 아직 확인하지 않음은 0이 아니라 미확인 상태다.

한 번 인정한 회차에 칭찬을 더했다는 이유로 기본 PASS를 자동 2개로 늘리지 않는다. 별도 칭찬 보너스는 독립 발행·출처로 남긴다. 하루 복수 회차가 허용되는 행동에서는 회차마다 인정하고 기간 한도를 적용한다.

### 제3조 플러스 행동과 마이너스 사건

보상형 행동과 패널티형 위반은 Lifestyle에 함께 속할 수 있으나 서로 다른 사실·조건·효과다. 예를 들어 정리 수행 인정과 명시된 방치 위반은 별도로 확인한다. 정리 스티커가 없다는 이유만으로 방치 위반을 자동 생성하지 않는다.

### 제4조 중간지대와 반복 기회

‘오늘 일부 정리를 했지만 보상까지는 인정하지 않음’이나 ‘인정 한도를 채워 추가 보상 없음’은 무효과로 설명한다. 생활습관의 중간지대는 부분 개선과 다음 기회를 보존한다. 같은 조건이 미래에 보상형 또는 패널티형으로 개정될 수 있어도 오늘의 결과를 새 기준으로 바꾸지 않는다.

### 제5조 인플레이션 관리

기간별 인정 횟수·총량과 합산 범위를 정한다. 한도를 넘겨도 실제 행동 기록은 보존한다. 스티커 누적을 보상 조건으로 쓰면 어느 종류를 얼마나 모았는지와 기본/추가 구간을 명시한다. 보상 없이 기록만 남기는 생활 행동도 허용한다.

### 제6조 패널티

위반 사건을 구체적으로 확인하고 차감 효과와 기간 한도를 별도로 적용한다. 부모의 유연한 PASS 인정이 패널티 무제한 재량으로 확장되지 않는다. 과거의 성취·스티커·물질적 보상을 자동 몰수하지 않는다.

### 제7조 약 복용 관련 기록 및 변화 관찰

자녀의 약 복용 관련 기록은 아침·저녁 2회 기록을 기본으로 하고 구조화된 약물 기록으로 관리한다. 양육일기는 선택 사항으로 두며 약물 기록과 관련된 변화 관찰을 보조할 수 있다. 이 기록과 선택적 양육일기는 변화 관찰의 보조 근거 및 병원 참조용으로만 사용한다.

기록 공란이나 늦은 기록을 실제 미복용으로 확정하지 않으며, 기록 자체에서 보상·패널티를 자동 산출하지 않는다. 구체적인 약물 기록 필드는 이후 명세에서 정한다. 이 조항은 약의 종류·용량·복용 시각을 의료적으로 결정하거나 진단·치료 판단을 대신하지 않는다.

사용자가 별도로 확인한 10월 생활습관 시행령 L-013은 수면·취침과 연동된 생활습관으로 유지한다. 저녁 19:30까지 미복용한 사실을 부모가 아이에게 직접 물어 확인한 경우에 한하여 -40분, 하루 1회로 정한다. 이는 이전 -3시간에서 완화한 개정이며, 약물 기록·양육일기 영역과 별도 규칙·별도 확인 사건으로 관리한다. 미기록·부모 미확인만으로 위반을 만들지 않으며, 복용 적정성이나 의학적 변화를 평가·차감 기준으로 확장하지 않는다.

### 제8조 시행령 필수 내용

Lifestyle 시행령에는 목적, 인정/위반 행동, 부모 확인 기준, 스티커 종류, 회차와 주기, 인정 횟수·총량, 기본/추가 보상, 무효과 이유, 패널티의 독립 발생 기준·승인·한도, 예외와 변경 효력일을 적는다.

## 6. 번호·개정·폐지 체계

### 6.1 규정 번호와 개별 규칙 번호

규정 문서 번호는 `PR-BASIC`, `PR-TASK`, `PR-QUEST`, `PR-LIFESTYLE`로 유지한다. 각 문서는 제1조부터 독립적으로 번호를 매긴다.

개별 시행 규칙에는 `T-001`, `Q-001`, `L-001`처럼 **종류별 영구 번호**를 부여한다. 초기 원문이 오기 전 활동별 번호와 금액을 미리 확정하지 않는다. 숫자는 화면 순서가 아니라 영구 식별자다. 표시 순서를 바꿔도 번호를 바꾸지 않는다.

### 6.2 버전과 종류 변경

같은 목적의 규칙 개정은 같은 영구 번호의 새 버전으로 남긴다. 예를 들어 `L-004 v1 → L-004 v2`는 기준 또는 보상이 개정된 관계다. 종전 버전의 시행 종료와 새 버전의 시행 시작을 기록한다.

Task에서 Quest로 관리 목적 자체가 바뀌면 `T-004`를 폐지하고 `Q-007`을 새로 제정하되 ‘승계한 규칙’ 관계를 남긴다. 원본의 번호를 덮어써서 과거 기록이 Quest였던 것처럼 만들지 않는다.

### 6.3 이력의 내용

제정·개정·폐지마다 전체 원문, 조문/규칙 번호, 버전, 변경 전후 내용, 사유, 작성자, 사용자 승인, 작성·승인·시행 시점과 이전 버전 참조를 남긴다. Grok 검토 의견과 반영/미반영 결정도 붙인다. 시행 종료 이후에도 과거 사건에서 당시 원문을 읽을 수 있어야 한다.

주중 개정에서 스티커 합계·한도를 이어갈지는 변경 시행령의 승계 조항에 명시한다. 버전이 바뀌었다고 자동 리셋하거나, 서로 다른 조건을 자동 합산하지 않는다.

## 7. 잔차를 처리하는 운영 규율

### 제1조 정상 결과를 잔차로 보내지 않음

중간지대, 스티커 미지급, 조건 미달, 인정 한도 초과는 이미 규정이 설명한 결과라면 잔차가 아니다. 미체크는 우선 확인 대기다. 반면 필요한 측정값을 끝내 확정할 수 없거나 시행령 자체에 공백·충돌이 있으면 해결 질문을 연결한다.

### 제2조 원사건 보존

원사건을 오늘 데이터와 잔차 데이터에 각각 복제해 서로 다른 정본을 만들지 않는다. 원사건에 잔차 질문을 참조로 붙인다. 동일 사건에 개념·측정·규정 충돌 등 여러 질문이 있을 수 있다.

### 제3조 해결의 종류

승인된 기존 규정으로 편입, 새 규정 제정 또는 개정, 맥락 기록으로 유지, 오류·중복 종결을 구별한다. AI가 추천해도 사용자 또는 권한 있는 사람이 최종 결정한다. 모르는 행위를 억지로 새 종류 정본에 넣지 않는다.

### 제4조 효과의 독립성

보류가 필요한 질문이 어떤 효과를 막는지 명시한다. 의미 관계가 하나 미정이라는 이유로 이미 확정된 모든 보상을 막지 않는다. 반대로 보상 기준 자체가 없는데 활동명만 안다고 효과를 추정하지 않는다.

### 제5조 결정과 적용의 분리

잔차가 해결됐다는 사실과 과거 보상·차감을 반영한다는 결정은 다르다. 새 규정은 원칙적으로 미래부터 시행한다. 과거 사건 편입과 소급 효과가 필요하면 적용 범위·원 수행일·결정일·효력일·정정 근거를 별도로 승인한다.

### 제6조 크론과 스냅샷

크론은 승인된 효과를 중복 없이 게시하는 절차이며 규정의 빈칸을 판단하는 주체가 아니다. 스냅샷은 그날의 관측 기록이지 규정이나 잔차 결정의 정본이 아니다. 잔차 때문에 기존 원장을 직접 고치고 크론을 반복 강제하는 방식은 쓰지 않는다.

## 8. 초기화 및 새 시행의 경과 규정

사용자가 요청한 ‘현재 법령과 런타임 초기화’는 **기존 정책의 신규 적용을 끝내고 새 승인 체계로 출발하는 전환**으로 정리한다. 개정·삭제 이력을 남긴다는 요청과 맞추기 위해 과거 문서·사건의 물리 삭제와 같은 의미로 처리하지 않는다.

초기 시행령을 받은 뒤 새 초안 묶음을 만들고 Manus 1차 정리 → Grok 2차 검증 → 사용자 확정 → 전환 기준시점 결정 순으로 진행한다. 각 기존 규칙의 종료·폐지와 새 규칙의 승계 여부를 연결한다.

가족·로그인·부모·자녀 연결·프로필은 규칙 초기화와 분리해 보존한다. 강화물 카탈로그는 재사용 목록이며 새 시행령이 채택한 항목을 참조할 수 있다. 기존 예약·배정, 미확인 사건, 이미 발생한 보상권은 각각 어떻게 닫거나 보존할지 전환명세에서 정한다. 새 규칙에 임의로 섞지 않는다.

운영 초기화 실행 전에는 정확한 가족·종료 대상·효력 시점·보상권 처리·보존 범위를 제시하여 확정한다. **이번 1차 문서 정리에서는 운영 초기화를 실행하지 않았다.**

## 9. 사용자 초기 시행령을 받는 형식

자유롭게 텍스트로 적어도 된다. 아래는 빠진 관계를 확인하기 위한 작성 순서다. 모든 숫자를 지금 채울 필요는 없으며, ‘없음’과 ‘미정’을 구별하면 된다.

1. **분류와 목적:** Task / Quest / Lifestyle 중 어디이며 어떤 습관·성취를 위한 것인가.
2. **행동과 확인:** 무엇을 했거나 어떤 일이 발생했으며 누가 어떻게 확인하는가.
3. **평가:** PASS 지급/미지급 또는 수량·정답률·시간·척도. 복수 조건이면 AND/OR와 경계.
4. **결과:** 보상·무효과·패널티의 범위. 중간지대가 없으면 이유.
5. **효과:** 스티커 종류, 보상 1, 선택 보상 2, 또는 차감. 단위와 지급/이행 방식.
6. **주기와 한도:** 일·주·월·이벤트, 실제 회차, 인정 횟수, 총량, 집계 범위.
7. **추가 달성:** 기본 이후 추가 기준인지, 상위 구간의 총액인지, 서로 배타적인지.
8. **예외와 변경:** 미확인·부분 수행·정정·적용 제외·변경 시점·이전 규칙 승계.

## 10. 현재 확정과 검토 대기의 경계
