# Play Routine 법령형 운영 구조 — 월별 승계·개정·강화물 확장 v0.1

**핵심은 ‘규정을 매달 복제하는 앱’이 아니라 ‘계속 유효한 규정의 버전을 월별 운영계획이 참조하는 앱’이다.** 11월에는 기존 규칙을 전부 새로 등록하지 않는다. 계속 적용할 것은 같은 규정·같은 버전을 참조하고, 바뀐 것만 개정·폐지·신설한다.

상태: Manus 1차 구조안, Grok 검토 전. 최신 사용자 확인은 반영했지만 새 구조는 아직 운영 DB·UI·원장에 적용하지 않았다. 문서의 ‘법령’은 Play Routine 내부 운영 규범이며 국가 법률이 아니다. 여기에 쓰는 v1/v2와 11월 변경 사례는 설명용이다. 현재 DB 버전번호·실제 11월 금액을 뜻하지 않는다.

## 1. 고정할 관계

```text
상위 기본법 PR-BASIC@버전
  ├─ Task 규정 PR-TASK@버전
  ├─ Quest 규정 PR-QUEST@버전
  └─ Lifestyle 규정 PR-LIFESTYLE@버전
       ↓ 각 하위규정을 따르는 개별 시행규칙
       T-001@버전 / Q-001@버전 / L-001@버전
       ↔ 공통 운영 시행규율@버전
       ↔ 강화물·효과 정의@버전
       ↓ 정확한 버전과 기간을 채택
       월별 운영계획@버전
       ↓ 자녀 배정·예정 회차·실제 수행
       부모 확인·판정
       ↓ 당시 규정 묶음을 고정 참조
       스티커·보상권·승인 차감 → 정산 → 불변 원장
```

공통 운영 시행규율과 강화물 정의는 세 하위규정을 덮어쓰는 더 높은 법이 아니다. 기본법과 관련 하위규정에 맞는 계산·기간·한도·제공 방식을 정의하는 참조 정본이다. 개별 규칙은 평가 기준과 적용할 공통 규율·강화물 버전을 함께 지정한다. UI가 공통 규율에 없는 기본값으로 규정을 대신하지 않는다.

### 상위에 둘 것과 하위에 둘 것

기본법에는 목적, 보상·중간지대·패널티의 의미, 권한, 기록 보존, 복수 보상 허용, 차감 금지 경계와 개정 원칙을 둔다. Task·Quest·Lifestyle 규정에는 각 대상의 인정·평가 원칙을 둔다. 공통 시행규율에는 시간대, 일·주·월 경계, 인정 횟수 처리, 잔액 하한, 정산·정정·이행 절차를 둔다. 구체 활동명·금액·횟수·요일·점수·소원 내용은 개별 시행규칙에 둔다.

예를 들어 ‘생활습관 전체의 일간 차감 상한을 허용한다’는 상위 원칙의 변화이고, ‘누구에게 어떤 상한과 주기로 적용한다’는 시행규율의 변화다. 어느 활동을 위반으로 인정할지는 개별 규칙의 독립 조건이다. 새 차감 방식을 추가했다고 이미 있는 활동 모두에 자동 적용하면 안 된다.

## 2. 영구 번호와 버전을 분리한다

규정과 개별 규칙에는 바뀌지 않는 ID와 사람이 읽는 번호를 함께 둔다. 번호는 가족의 규정 범위 안에서 유일하다. 화면 순서를 바꾸거나 월이 바뀌어도 번호를 바꾸지 않는다. 기본법, 하위규정, 공통 규율, 강화물 정의, 개별 규칙, 월별 운영계획은 각각 독립적인 버전을 가진다.

같은 목적의 규칙에서 금액·조건·횟수·일정을 바꾸면 같은 ID의 새 버전이다. 관리 목적이 Task에서 Quest로 바뀌거나 기존과 별개 의무가 생기면 새 번호를 만들고 이전 규칙과 승계·대체 관계를 남긴다. 외형상 비슷하다는 이유만으로 계보를 합치지 않는다.

승인된 버전의 원문과 구조화 조건은 변경하지 않는다. 게시 후 오기를 고치거나 결과가 달라지는 변경은 새 버전과 변경 사유로 남긴다. 초안 수정은 가능하지만 승인·검토 이력을 소거하지 않는다.

## 3. 다섯 가지 변경 사건

| 처리 | 언제 쓰는가 | 과거 기록 | 다음 달 처리 |
|---|---|---|---|
| 계속 적용 | 내용이 그대로이며 종료되지 않음 | 같은 버전 유지 | 같은 버전 참조 |
| 개정 | 같은 규칙의 금액·조건·방법 변경 | 옛 버전 보존 | 새 버전 채택 |
| 폐지 | 해당 규칙을 더 이상 시행하지 않음 | 번호·원문·원장은 보존 | 폐지 효력 이후 새 회차 생성 안 함 |
| 신설 | 기존에 없던 독립 규칙 도입 | 새 영구 번호 | 새 버전 채택 |
| 해당 월 미채택 | 유효한 규칙이나 이번 달만 운영하지 않음 | 규칙 자체는 존속 | 다음 달 다시 채택 가능 |

‘10월 중간고사 종료’는 지정 이벤트 종료이지 Quest 기본법 폐지가 아니다. ‘11월에 Special 없음’도 Special 기능 삭제가 아니다. 월별 채택에서 빠졌다는 사실과 영구 폐지를 구별한다. 폐지 후 같은 목적을 다시 도입할 때는 재시행 결정과 버전·계보를 남기며 옛 폐지 사건을 지우지 않는다.

## 4. 월별 운영계획은 복사본이 아니라 채택 목록이다

월별 계획에는 운영 월, 적용 시간대, 계획 버전, 승인 시각, 채택한 규칙 ID·정확한 버전·적용 구간·자녀 범위를 둔다. 개별 규칙의 전문과 금액을 다시 복제하여 별도의 정본을 만들지 않는다.

11월 준비 화면은 10월 계획에서 ‘계속 유효한 규칙’을 제안 목록으로 가져올 수 있다. 부모는 그대로 유지·개정·이번 달 제외·폐지·신설을 선택한다. 바뀌지 않은 규칙은 다시 입력하지 않는다. 그러나 11월 운영을 승인하기 전, 이벤트 종료·기존 종료일·새 상위규정 충돌을 확인하고 실제 채택할 정확한 버전을 잠근다. **준비 목록의 자동 승계와 승인된 운영계획의 확정은 별개다.**

월별 계획이 참조하는 버전을 ‘현재 최신’으로 자동 추종하지 않는다. 계획 승인 뒤 개정이 생기면 계획의 새 버전 또는 승인된 변경 묶음을 만들며 적용 시점 이후 회차에 연결한다. 여러 규칙의 개정은 한 변경 묶음으로 검토·승인하고 전부 충족할 때 원자적으로 게시한다. 일부만 새 상위 규정으로 바뀌는 반쪽 게시를 막는다.

### 10월→11월 예시

| 실제 규칙 또는 예시 | 11월의 처리 | 바뀌지 않아야 할 것 |
|---|---|---|
| 학교 T-007, 0~4개 없음·5~7개10,000원·8개 이상총15,000원 | 변경 없으면 같은 버전 채택 | 기본+상위 이중 지급 금지 |
| 고양이 화장실 L-001, +15분·하루3회 | 변경 없으면 같은 버전 채택 | 기존 사건·인정 한도 이력 |
| Q-003 10/19~22 중간고사 | 기간 종료, 11월은 미채택 | 과거 성적·보상권 보존 |
| 가상: 학교 5~7개 금액을12,000원으로 변경 | T-007의 새 버전, 미래 시행 | 10월을12,000원으로 재계산하지 않음 |
| 가상: 새로운 보상 제공 방식을 추가 | 강화물·효과 정의 신설 후 채택 | 원·분·포인트의 과거 단위 유지 |

## 5. 상위 규정 개정은 영향 분석을 거친다

상위 기본법 또는 하위규정의 새 버전은 어떤 하위 규칙·공통 규율·운영계획에 영향을 주는지 먼저 목록으로 만든다. 각 항목을 내용 변경 없이 호환, 개정 필요, 이번 적용 제외로 분류한다. ‘호환’도 검토한 상위 버전과 검토 결과를 기록한다.

하위 규칙의 내용이 그대로 호환되면 금액과 행동 문구를 억지로 복제할 필요는 없다. 다만 새 운영계획은 새 상위 버전과 그 규칙 버전이 호환된다는 정확한 연결을 고정한다. 호환되지 않으면 하위의 새 버전을 승인하기 전에는 새 조합을 게시하지 않는다. 기존 유효 조합은 명시된 종료 시점까지 존속하며 새 상위 규정을 이유로 과거 판정을 조용히 바꾸지 않는다.

새 상위 규정이 즉시 금지하는 방식이 생기면 적용 영향과 종료·보류 범위를 명시한 전환 결정을 함께 승인한다. 이를 ‘계속 호환’으로 처리하지 않는다. 어떤 버전을 언제 알았는가와 어느 수행기간에 적용하는가는 별개로 남긴다.

## 6. 보상·강화물의 변경도 같은 원칙이다

강화물 카탈로그의 영구 ID, 정의 버전, 조건에 연결한 구체 보상, 실제 발생 보상권을 분리한다. 카탈로그는 여러 활동이 재사용하는 목록이다. 활동마다 같은 강화물을 새로 등록하지 않는다.

각 정의 버전에는 표시 이름, 자산 종류와 단위, 수치형/내용형 입력 계약, 제공 방식, 관련 공통 규율 버전을 둔다. ‘쿠페이머니 20,000원’과 ‘현금 20,000원’은 숫자가 같아도 제공 방법과 잔액이 같다고 가정하지 않는다. 시간을 원으로 자동 환산하지 않는다. 소원·체험의 내용은 당시 보상권에도 고정한다.

| 변경 사례 | 처리 |
|---|---|
| 이미 있는 시간 강화물을 다른 활동에 연결 | 기존 정의 버전 선택, 새 카탈로그 항목 불필요 |
| 같은 강화물의 금액·조건별 수량 변경 | 해당 개별 규칙 새 버전 |
| 같은 강화물의 제공 방법·표시 명칭 변경 | 정의 새 버전, 미래 규칙에서 채택 |
| 원 자산을 분·포인트처럼 차원이 다른 단위로 변경 | 원칙적으로 새 자산 ID와 승계 관계, 기존 잔액 환산은 별도 승인 |
| 새로운 체험·새 보상 방식 추가 | 새 정의·입력 계약·지원 처리기 검증 후 활성화 |
| 사용 중 강화물 폐지 | 신규 선택/권리 발생만 종료, 과거 보상권과 이행 의무 보존 |

현재 공통 기획은 한 조건에 보상 1~2개이며 두 번째는 선택이다. 보상 제공 방식의 종류가 늘어나도 이 두 번째 보상을 필수로 바꾸지 않는다. 앞으로 조건당 개수 제한을 늘리려면 공통 계약 개정과 영향 분석이 필요하다. 카탈로그에 새 항목을 추가하는 일과 보상 개수 정책을 바꾸는 일은 별개다.

## 7. 자료 추가로 가능한 변화와 개발이 필요한 변화

등록된 효과 처리기가 이미 지원하는 금액·횟수·기간·보상 항목 변경은 검증된 새 데이터 버전으로 처리한다. 새로운 외부 예약 API, 다른 계산 논리, 지원하지 않는 복합 차감 방식은 관련 규정 개정만으로 실행할 수 없다. 입력 스키마, 권한, 처리기 버전, 단위, 테스트, 재전송 방지 키를 개발·검증해야 한다.

임의 JavaScript·SQL·모델이 만든 코드를 규정 텍스트에 넣어 실행하지 않는다. ‘패널티 방식 추가’는 승인된 계약을 따르는 처리기 등록이며 무제한 사용자 코드를 실행하는 기능이 아니다. 지원하지 않는 정책은 초안·검토 상태로 남기고 실제 원장 반영을 막는다.

## 8. 달력·반복과 실제 회차를 분리한다

사용자 확인: **T-006 영재원 수업은 2026-10-24 토요일, 수행 완료 보상240분**이다. 통상적인 일정은 격주 토요일이다. T-005 토요일 문제 수업은 실제 영재원 수업이 없는 토요일에 적용한다.

반복 일정에는 기준 날짜, 반복 간격, 요일, 적용 기간, 휴강·보강 예외를 둔다. ‘격주 토요일’의 일반 템플릿과 실제 채택된 회차는 구별한다. 기준 날짜·예외를 확정하기 전에는 11월의 모든 격주 후보를 실제 수업이라고 확정하거나, 과거10/10 회차를 소급 생성하지 않는다. 휴강·보강은 회차의 변경/취소 이력을 갖는다. 월이 바뀌어도 격주 기준점을 매월1일로 리셋하지 않는다.

T-005와 T-006은 확정된 수업 일정에서 배타 적용한다. 같은 수업 참여를 ‘문제 수업60분’과 ‘영재원 수업240분’으로 두 번 보상하지 않는다. 같은 날짜에 별개 활동이 실제로 있다면 사건·목적을 구별하고 별도 승인한다.

## 9. 기간·한도·스티커의 승계

규칙이 계속 적용되는 것과 일·주·월 집계가 계속되는 것은 다르다. 주간 규칙이 10월에서11월로 이어져도 같은 주를 두 달에서 각각 지급하지 않는다. 기간 키는 자녀·집계 범위·기간 시작/끝·시간대를 기준으로 하며 월별 계획 ID만으로 한도나 보상권을 새로 만들지 않는다.

규칙이나 강화물 정의가 주중 개정되면 이미 쌓인 인정 횟수·스티커·보상권을 이어갈지, 구·신 기준을 분리할지 명시적 전환 조항을 둔다. ‘규칙 버전이 달라졌다’는 이유로 한도를 자동 초기화하지 않는다. 서로 다른 활동의 스티커를 그림이 같다는 이유로 합산하지 않는다. 학교 스티커의 주간 범위는 학교 T-007이며 다른 생활습관 스티커가 아니다.

T-007의 확정 총액형은 같은 주에 기본10,000원과 상위15,000원을 합산하지 않는다. 이미 지급한10,000원에서 상위로 올라가면 추가5,000원이다. 미확인 회차는0개로 치환하지 않는다. 정정으로 외부 이행액을 회수해야 하는 문제는 자동 차감과 분리하여 승인·검토한다.

## 10. 과거 기록이 새 카탈로그를 따라 바뀌지 않게 한다

회차·부모 확인·평가에는 당시 규정 ID/버전, 상위·하위·공통 규율 버전, 월별 채택 버전, 일정 회차, 효과·강화물 정의 버전의 고정 연결을 둔다. 발생 효과는 당시 수량·단위·소원 내용과 사실 기준을 고정한다. 프로그램의 계산기 버전도 남겨 같은 입력을 재현할 수 있게 한다.

원장·이미 발생한 보상권·외부 이행 기록을 월 전환이나 폐지로 삭제하지 않는다. 과거 정정은 원기록 참조와 정정 결정·사유·적용일을 갖는다. 새 규정으로 과거를 계산하려면 별도의 소급 승인 범위를 명시해야 하며, 과거 잔액 사진을 덮어쓰지 않는다.

모든 부모·자녀·보호자 데이터의 참조는 같은 가족 범위임을 확인한다. 자녀는 자기 기록을 보고, 부모만 규정·계획을 승인하며, 조회 전용 보호자는 상태 열람만 한다. 검토용 AI 응답은 승인 기록을 대신하지 않는다.

## 11. 관계형 모델로 고정할 최소 구조

| 정본/기록 | 관계와 역할 |
|---|---|
| 규정 ID + 규정 버전 | 기본법·하위규정·공통 규율의 영구 정체성과 원문/상태/효력 |
| 규칙 ID + 규칙 버전 | T/Q/L 개별 의무의 계보와 조건·보상·기간 |
| 위계·호환 연결 | 정확한 상위 버전과 하위/개별 버전의 허용 조합, 검토·승인 |
| 변경 묶음 + 변경 사건 | 계속·개정·폐지·신설·월 미채택, 사유와 전환조항 |
| 월별 계획 + 채택 버전 | 규칙/자녀/적용 구간을 참조, 규칙 전문 복제 금지 |
| 효과/자산 ID + 정의 버전 | 단위·입력 계약·제공 처리기, 과거 권리 보호 |
| 반복 템플릿 + 실제 회차 | 격주 원칙과 확정·휴강·보강의 분리 |
| 사실·부모 확인·평가 | 수행일·입력일·확인일·적용 규정 묶음 고정 |
| 기간 집계 + 한도 사용 | 일·주·월·사건 범위, 월 전환 중복 방지 |
| 효과 발생·보상권·원장·이행 | 달성권·예정·사용 가능·실제 제공의 분리 |

이 표는 추가 설계의 계약이며 기존 DB에 이미 이런 엔티티가 완성되어 있다는 뜻이 아니다. 기존 가족·초대·규칙·회차·감사 테이블은 재사용하고, 새 규정 버전·계획·호환 관계를 연결하는 증분 마이그레이션이 필요하다.

## 12. 승인·게시 절차

초안 작성 → Manus 구조 정리 → Grok 독립 검토 → 사용자 쟁점 확정 → 영향 분석·지원 기능 검사 → 변경 묶음과 전환 기준시점 승인 → 미래 적용분 게시 순이다. Grok 의견도 자동 승인되지 않는다.

초기 체계 전환은 기존 규칙의 신규 적용 종료·새 규칙 채택·기존 사건/보상권 처리 범위를 따로 정한다. 이전에 사용자가 요청한 초기화와 개정 이력 보존을 동시에 만족시키며, 규정 원문·가족 연결·프로필·강화물·과거 사실을 임의 삭제하지 않는다. 이 문서를 작성하거나 검토 API를 호출했다고 운영 전환이 실행되지는 않는다.
