# Play Routine — 10월 26개 규칙 실제 적용 안내

**기준일: 2026-10-18 · 적용 대상: 현재 연결된 활성 가족 1개와 자녀 1명**

## 결론

Quest 3개, Task 7개, Lifestyle 16개를 실제 Supabase PostgreSQL의 독립 `october_*` 운영층으로 설치하고 자녀에게 채택했다. 적용 기간은 **2026-10-18 이상, 2026-11-01 미만**이다. 기존 계정·자녀 연결·활동·초안·강화물·기존 보상 기록을 초기화하거나 변환하지 않았다.

이 문서의 이전 설치 시점에는 학교 스티커 보상 자산을 `school_asset=PENDING`으로 남겼다. 이는 역사적 설치 사실이며 원본 불변 규정·버전을 수정한 것이 아니다. 현재 runtime projection은 사용자의 2026-10-18 02:55 KST 확정 답변에 따라 `school_asset=COUPAY_KRW`로 표시한다. T-007은 기본·칭찬 스티커 합계 0~4개 무보상, 5~7개 쿠페이 총 10,000원, 8개 이상 쿠페이 총 15,000원이며 5개에서 8개로 상향할 때 차액은 5,000원이다. 스티커 효과와 금융 권리는 혼합하지 않으며, PENDING fallback은 보존한다. 바이올린 보상량은 여전히 NULL이며 0분 보상을 발행하지 않는다.

이는 법령형 범용 그래프/월별 승계 설계 전체를 설치한 것이 아니다. 기본법·3대 규정 문서와 이번 운영층은 provenance로 연결되지만, School 격상 승인·자동 알림·잔차 분류·일반 원장 정산 등은 별도 후속이다.

## 부모의 사용 순서

1. 부모 로그인 후 첫 화면의 **운영표**에서 자녀와 수행일을 확인한다.
2. 일반 최초 보상은 해당 행의 **PASS**를 누른다. 시험·학교·토요일 수업·패널티·정정은 **확인·정정**을 열어 사실을 입력한다.
3. 같은 날 생활 행동이 더 있었다면 해당 행의 **회차 추가**를 누른다. 실제 행동은 보존하고 인정 한도만 적용한다.
4. 학교 확인은 문제 없음/문제 있음과 별도 칭찬을 입력한다. 기간 마감은 **보상·원장** 탭에서 시작일과 종료일(미포함)을 직접 선택한다.
5. 보상권 발행과 앱 밖 제공은 다르다. 제공한 뒤에만 **이행 기록**을 누른다. 패널티는 현재 차감 예정이며 실제 잔액 차감·자동 회수는 하지 않는다.

패널티에는 부모 사유가 필수이고 마지막 확정 대화창이 있다. L-013은 부모가 아이에게 직접 물어 복용 여부를 확인해야 한다. 약물 기록/양육일기 공란을 미복용 근거로 사용하지 않는다. L-015와 L-016이 같은 파손이면 같은 사건 ID를 선택해 두 규칙 모두 검토 보류로 남긴다.

상단 메뉴는 **운영표 / 규정 / 보상·원장 / 강화물 / 설정**이다. 운영표는 고정 머리글·식별열을 가진 한 개 HTML 표이며 모바일에서는 표 안을 가로/세로로 스크롤한다. 규정 탭에는 26개 전체 조건을 표시한다. 기존 관리 도구·계정 연결·보호자·CSV는 접어서 보존했다. 강화물 메뉴는 기존 재사용 카탈로그로 연결하며 작성 중 초안을 리셋하지 않는다.

## 관계와 계산 경계

```text
가족·활성 자녀
  → 시행령 정체성 → 불변 시행령 버전
  → 규칙 정체성(Q/T/L 코드) → 불변 조건·효과 버전
  → 10월 계획 → 자녀별 26개 채택
  → 수행일·회차 원사건 ↔ 추가만 가능한 제출·확인 사건
  → 일일 한도 / 시험·학교 기간 bucket
  → 자산별 보상권·차감 예정 권리 → 별도 앱 밖 이행 기록
  ↘ 제한 필드 감사 사본(play_audit.events)
```

- **원사건과 인정은 분리:** L-001 네 번 수행은 네 행으로 남고 세 번만 인정된다. 초과는 `LIMIT_EXCEEDED`이며 삭제하지 않는다.
- **스티커 종류는 구별:** `SCHOOL_BASIC`과 `SCHOOL_PRAISE`는 서로 다른 저장 코드다. 표시 아이콘이 같아도 원천·규칙·수행일·확인 revision이 구별된다. 금융 자산 권리로 잘못 발행하지 않는다.
- **최고 구간은 최종총액:** Q-003은 전체 시험창에서 360→480→600으로 상향하면 +120, +120만 추가한다. 학교 쿠페이는 5~7개 총 10,000원에서 8개 이상 총 15,000원으로 상향하며 5,000원만 추가한다. 0~4개는 무보상이다.
- **미확인은 0이 아님:** 학교 미확인·문제+칭찬 동시 사례는 마감을 막는다. 후자는 `REVIEW_REQUIRED`다.
- **하향 정정은 삭제·회수 아님:** 목표가 기존 발행보다 작아지면 기존 권리와 이행을 검토 상태로 보존한다. 검토 권리를 합계에서 빼고 전액을 다시 발행하는 우회도 하지 않는다.
- **보상권은 잔액이 아님:** 오늘 화면은 선택 수행일의 확인된 예정 효과다. 현재 보유량은 일반 원장 미연결로 `—`이며 사용 가능한 시간이나 실제 송금 내역을 뜻하지 않는다.

## 설치와 검증

실제 운영 DB에 `0021_october_runtime.sql`과 `0022_october_audit.sql`을 설치했다. 기존 0001–0020 파일의 설치 해시는 그대로 검증됐고, 기존 38개 public 테이블 행 수·내용 해시는 변경 전 스냅샷과 비교한다. 이번 seed는 기존 자료를 수정하지 않으며 새 버전·채택만 추가한다.

설치 전 실제 PostgreSQL의 **56개 운영 반례와 16개 신규 감사 검사**를 한 트랜잭션에서 시험한 후 전부 롤백했다. 아직 미래인 10/19–31 시험은 관리자 시험 트랜잭션 안에서만 날짜 helper를 10/31로 바꿨으며 helper 변경·가짜 계정·수행·보상·이행 모두 롤백했다. 이를 실제 아이의 성취나 지급으로 기록하지 않았다.

신규 12개 테이블은 RLS가 켜져 있고 raw authenticated table 쓰기는 닫혀 있다. 활성·이메일 확인된 부모/자녀를 `auth.uid()`로 확인하며, 부모 확인·학교 마감·이행은 부모만 가능하다. 자녀·보호자·다른 가족의 쓰기 거절을 시험한다. 보호자는 기존 조회 전용 상태판을 유지하며, 신규 10월 상세 규정·사유 전체를 보호자에게 공개하는 기능은 이번 범위가 아니다.

각 신규 테이블의 AFTER 감사 트리거는 기존 append-only `play_audit.events`에 제한 필드만 기록한다. 사유·의료/점수 metrics·규정 원문·조건/효과 JSON·재전송 payload·원문 이름은 감사 사본에서 제외한다. 실제 seed 설치는 관리자 **DATABASE_SESSION**으로 기록되며 부모가 웹에서 로그인해 눌렀던 사건으로 가장하지 않는다. 승인 대상 부모 principal과 원문/seed 해시는 시행령 provenance에 따로 남긴다.

두 DB 연결의 동일 일일 한도 키 대기/해제를 별도 롤백 시험으로 확인한다. 이는 실제 PostgreSQL advisory lock 직렬화 시험이며, 여러 실제 지급을 commit하는 경쟁 시험이나 자동 송금 시험이라고 주장하지 않는다.

## CSV와 후속 범위

설정·기록 내려받기에 `october-records`와 `october-rights`를 추가했다. 둘 다 부모 인증과 서버 가족 필터가 선행하며 수식 접두사 무력화를 유지한다. 현재 CSV는 **발생 행의 최신 확인 스냅샷과 권리의 최신 상태**다. 불변 제출/확인 사건 및 상세 이행 사건은 DB에 보존되지만 해당 전체 사건 이력을 내보내는 CSV는 이번 범위가 아니다. 빈 자료에서도 헤더를 유지한다.

후속으로 남는 것은 바이올린 보상량 결정, 일반 시간 원장·사용가능 잔액·자정 정산 연결, 법령형 월별 승계/School 격상 승인 UI, 보호자의 신규 10월 요약 연결이다. 학교 쿠페이 금액표는 현재 runtime 표시 범위에서 확정했지만, 이 문서는 새 버전 덮어쓰기나 이행 완료를 주장하지 않는다. 이들은 설치된 이번 26개 규칙의 실제 수행 기록과 혼동하지 않는다.
