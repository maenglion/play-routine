# Play Routine 관계형 모델 설계 패키지 v0.1

기준일: 2026-10-16. 기존 Word 구조·관계 검토안을 엔티티·FK·물리 필드·처리 계약으로 구체화한 설계입니다. **운영 DB·소스·배포·기존 입력은 변경하지 않았습니다.**

## 먼저 읽을 파일

| 파일 | 용도 |
|---|---|
| `Play-Routine-Relational-Model-v0.1.docx` | 구조·관계·운영 규칙 검토용 Word. 마지막에 추가 의견 작성란 |
| `Play-Routine-Relational-Model-v0.1.md` | 같은 설계 본문 + 52개 엔티티의 전체 필드·FK·유일성 사전 |
| `Model-Overview.png` | 정본 → 회차 → 부모 확인 → 인정 → 권리 → 원장/이행의 한 장 흐름 |
| `ERD-Core.png` | 주요 엔티티의 1:N·선택 관계 |

`Model-Overview.mmd`는 한 장 흐름도의 편집 가능한 원본입니다. SQL은 기존 실제 인증 테이블을 새로 만들라는 뜻이 아닙니다. 52개 엔티티 중 4개는 기존 가족·계정·자녀·활동을 표현하는 축약 앵커입니다.

## 검증과 한계

- SQL을 인메모리 PostgreSQL(PGlite)에 생성하고 가족 간 FK, 하루 4회 기록, 중복 회차, 수량 150, 복수 효과 방향, NaN·소수량, 원장 불변, 중복 적립, 정확한 상쇄, 외부 자산 중복 적립 차단을 시험했습니다.
- 한도·잔액·판정 엔진·정산 실행·부모/자녀/보호자 운영 RLS·실제 다중 세션 동시 처리는 구현/시험하지 않았습니다.
- 권한 없는 클라이언트 직접 쓰기를 허용하는 파일이 아닙니다. PUBLIC 권한 회수와 RLS default deny를 포함하되, 실제 RPC와 역할별 정책은 별도 구현 대상입니다.
- 현재 등록된 다섯 룰은 조회 시점의 값으로 매핑했고, 설명/점수/시간 충돌은 사용자 확인 후 새 버전으로 해결해야 합니다.
- 보상/차감의 자정 확정 원칙은 유지합니다. 실제 사용을 즉시 차감할지 자정까지 예약할지는 미확정으로 명시했습니다.
- 한도를 없애거나 임의 한도 숫자·패널티 기본값을 넣지 않았습니다. 패널티 표식·차감 승인·실제 원장 거래는 별도입니다.

## 검증 재현용 파일

Node.js 환경과 `package.json`의 의존성이 준비된 뒤 `npm run verify`로 실행할 수 있습니다. 외부 Supabase URL·API 키·DB 비밀번호는 필요하지 않습니다. 검증은 메모리 DB만 사용하며 운영 테이블을 건드리지 않습니다.

5. 원장·외부 이행·사용 정책·자정 정산.
