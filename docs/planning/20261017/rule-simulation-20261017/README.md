# Play Routine 조건 대입 시뮬레이션 — 2026-10-17

이 패키지는 사용자가 요청한 **예전 조건 + 새로 입력한 조건**을 2026-10-16의 관계형 설계에 실제 행으로 대입하여 시험하는 용도입니다. 운영 앱, Supabase, 실제 자녀 계정·배정·쿠폰·지급은 변경하지 않습니다.

## 어떤 자료를 썼는가

- 과거 운영 시트 `05_rule_conditions`의 27행: 2026-10-16 저장된 읽기 자료. 원문 조건은 `source-old-conditions.json`에 포함.
- 같은 날 조회된 새 게시 룰 5개: 학교생활, 밀크티 학습지, 기초연산 2000, 기탄 하루 3장, 기탄 20문제 3분 시험.
- 기존 v0.1 참조 SQL의 52개 엔티티: `reference-model.sql`. **실제 운영 migration이 아닙니다.**

오늘의 운영 DB를 새로 조회한 자료가 아닙니다. 이후 사용자가 입력·수정한 부분이 있다면 이번 보존본과 다를 수 있습니다.

## 실행 파일

| 파일 | 내용 |
|---|---|
| `scenarios.json` | 규칙 카탈로그·출처·46개 예시·별도 기대값 |
| `condition-mapping.csv` | 과거/최근/비교안 조건을 엔티티에 넣는 입력 관계표 |
| `engine.mjs` | 테스트 전용 판정·인정·정산 어댑터. 저장한 조건을 읽고 실제 PGlite DB에 사건·권리·원장 행 기록 |
| `reference-model.sql` | 원본 52개 테이블·FK·불변 제약 |
| `output/results.json` | 기대값과 실제 실행값 비교 |
| `output/ledger.csv` | 원장 거래·실제 귀속일·효력·상쇄 근거 |
| `output/relations.csv` | 시나리오별 관계 테이블 저장 건수 |
| `output/DB-state.json` | 예시 DB 행 사본. 실제 사용자의 ID·이메일·비밀번호 없음 |

Node.js 환경에서 패키지 의존성을 설치한 뒤 `npm run simulate`로 재현할 수 있습니다. 외부 API 키·DB 비밀번호는 필요하지 않습니다. 실행하면 `output`에 예시 결과만 새로 기록합니다.

## 비교안과 확정된 값의 차이

`source=NEW`는 10/16 당시 실제 저장값, `source=OLD`는 과거 조건표의 읽기 값, `source=PROPOSAL`은 **별도의 시험 가정**입니다. PROPOSAL을 운영에 게시하지 않습니다.

- 주간 월요일 시작·달력 월·Asia/Seoul은 시험을 위해 명시한 경계입니다. 사용자 운영 주기 확정이 아닙니다.
- 하루 청소 2회는 조건표, 1회는 노드 메모를 각각 다른 사례로 비교합니다. 어느 쪽도 새 정본으로 몰래 선택하지 않습니다.
- 두 학습 합산 하루 60분, 월 시험 인정 2회, 두 보상의 부분 인정은 구조가 수용하는지를 비교하는 임시 가정입니다.
- 새 기탄 시험의 **저장된 80% 기준**과 **설명에 적힌 정답 15개·3분 AND 기준**을 따로 실행합니다. 실제 등록값을 75%로 변경하지 않습니다.
- 과거 비활성 완화 -80/-50은 별도 비교안에서만 시험합니다. 약·전액 몰수·초과 ×3은 실제 발행 대상에서 제외합니다.
- 과거 월간·주간 미달은 부모가 해당 기간 실패를 명시한 사실로만 시험합니다. 예정량·준수율의 새 분모를 임의 생성하지 않습니다.
- 단위 WON·서비스 POINT는 외부 이행 사본이고, MIN은 내부 원장 예시입니다. 실제 송금/쿠페이 충전/소원 실행을 하지 않습니다.
- 패널티 시험의 시작 여유량 600분은 명시한 테스트 보너스입니다. 실제 시작 잔액이 아닙니다.
- 모두 가정한 수행 사실입니다. 실제 아이가 했다는 데이터로 해석하면 안 됩니다.

## 검증 한계

단일 독립 PostgreSQL 엔진의 테스트 어댑터입니다. **운영 RLS·부모/자녀 로그인·다중 세션 한도 경합·실제 자정 스케줄러·외부 송금·사용 후 취소 부채를 검증한 것이 아닙니다.** 테이블에 값을 넣고 판정이 되는 것과 운영 시스템 배포 완료는 구별합니다.

기존 게시 룰에 있는 의미 충돌(점수/수량, 60 이하/미만, 60분/80분, 75%/80%, 서비스 포인트/원화)은 실행 결과 차이를 보고 사용자가 별도로 정해야 합니다. 기존 룰/활동/자녀 연결을 수정·삭제하거나 과거 시트 데이터를 이관하지 않았습니다.

최종 실행: 46/46 시나리오 및 별도 최종값·중간 상태 246/246 확인 통과. 원본 SQL 52개 테이블 중 45개에 예시 3,599행이 저장됐습니다. 두 효과 취소 시 횟수 예약은 한 번만 해제되고, 겹친 배타 조건은 둘 다 보류하는 반례까지 포함했습니다.

`output/DB-dump.sql`은 조사용 INSERT 행 목록으로, FK 의존 순서까지 정렬한 복원 파일은 아닙니다. 재현은 제공된 `engine.mjs`와 `scenarios.json`을 사용하세요. 실제 저장 건수 집계는 `output/Table-Counts.csv`, 행별 참조는 `output/relations.csv`입니다.
