# Play Routine 부모 운영표 프로토타입

상단 메뉴 **운영표 / 규정 / 보상·원장 / 강화물 / 설정·기록**으로 긴 단일 관리 화면을 나눈 React·TypeScript 코드다. 실제 Supabase, 부모·자녀 로그인, 원장, 이메일, 송금·쿠페이 충전 API는 연결하지 않았다. 기존 앱 파일과 운영 데이터도 변경하지 않았다.

## 화면 동작

운영표의 첫 샘플에는 L-001 수행 4건이 들어 있다. `현재 표 정상 회차 일괄 인정`을 누르면 3건만 인정하고 4번째는 원사건을 보존한 채 한도 초과로 남긴다. 예정량은 45분이며 실제 쿠폰 잔액이 아니다. 미정 규칙과 패널티는 이 일괄 처리에서 제외한다.

`학교 이번 주`에서는 기본 인정 0/1과 교사 칭찬을 별도로 기록한다. 미확인·피드백 누락·문제+칭찬 미정 조합은 마감을 보류한다. 확인된 5~7개는 총 10,000원, 8개 이상은 총 15,000원이다. 기존 10,000원 권리를 발행했다면 추가권리는 5,000원이며 실제 지급은 별도 기록이다. 이 화면의 중간발행은 차액 계산을 보여주는 **모의 비교 예시**이지 일반 중간지급 승인 기능이 아니다.

규정 페이지에는 Task 7개·Quest 3개·Lifestyle 16개를 번호와 미정 상태로 표시한다. 규정의 실제 게시·개정·폐지 편집은 구현하지 않았다. 강화물 등록은 모의 카탈로그에만 적용한다. 설정에서는 이 브라우저의 모의 기록 CSV와 모의 데이터 초기화만 제공한다.

## 한 단계씩 실행

Node.js 22 이상이 있는 환경에서 먼저 이 `prototype` 폴더를 연다. 최초 실행에는 `npm ci`로 의존성을 설치한다. 설치가 끝난 뒤 `npm run dev`를 실행하고 `http://localhost:5176/operations`를 연다. 두 명령을 한꺼번에 실행할 필요는 없다.

코드 검사는 `npm test`, 배포용 정적 파일은 `npm run build`로 만든다. `dist/`는 정적 호스팅용이며 운영 DB 연결을 포함하지 않는다. SPA 호스팅은 `/operations`, `/regulations` 등의 경로를 `index.html`로 재작성해야 한다. 동봉한 `_redirects`가 Netlify에서 이를 처리한다. 기존 Play Routine 사이트를 이 코드로 교체하지 않는다.

## 프로토타입 경계

브라우저 저장 키는 `play-routine-ordinance-prototype-v1`이다. 로컬 저장은 진짜 감사·보안·동시성 기능이 아니다. 서버 통합에서는 가족별 RPC, 원사건·확인 revision, 멱등키, 안정 한도 버킷, 권리별 이행을 사용해야 한다. 권한 있는 사용자 ID를 화면 인자로 보내 신뢰하지 않는다.

학교 샘플 기간 2026-10-19~25는 월요일 시작 **예시**다. 사용자 주간 경계는 아직 미확정이다. SQL에서는 끝을 제외하는 `[2026-10-19, 2026-10-26)`로 표현한다. 바이올린 보상·점검 횟수/차감 한도·전체 상한 등 미정 항목은 값 0이나 자동 차감으로 대체하지 않는다.

폰트는 Google Fonts의 Noto Sans KR을 요청하며 네트워크가 없으면 시스템 한글 글꼴을 사용한다. 표는 하나의 HTML table 안에서 머리글을 고정하고 모바일에서는 표 영역만 가로 스크롤한다.
